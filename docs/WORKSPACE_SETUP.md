# Работа с проекта на двух компьютерах

Как настроить второй компьютер (ноутбук), чтобы работать над TTC и там, и там: днём в кофейне, вечером дома.

Короткий ответ: **переносить сессию не нужно и не получится — нужно перенести состояние проекта, а оно уже в git.** Проект специально так и устроен: всё, что нужно знать о нём, лежит в [PROJECT.md](../PROJECT.md), а не в истории переписки. На новом компьютере достаточно сказать `/project-load` — и Claude прочитает PROJECT.md и будет знать проект целиком, без изучения кода.

Ниже — что именно надо перенести один раз.

---

## 1. Что едет само (через GitHub)

Ничего делать не надо, просто `git clone`:

- весь код бота, миграции, тесты;
- **PROJECT.md** — главный файл: архитектура, прогресс, журнал сессий, найденные баги. Это и есть «память» проекта;
- документация в `docs/` (включая эту страницу);
- `.claude/settings.local.json` — разрешения для Claude Code в этом проекте.

```bash
git clone https://github.com/ArdenKayr/TTC.git
cd TTC
```

## 2. Что придётся перенести руками (один раз)

Это то, что намеренно не лежит в git — секреты и настройки самого Claude Code.

### 2.1. Файл `.env` (обязательно)

В нём токен бота и пароли. В git его нет и быть не должно. Скопируйте с компьютера на ноутбук любым безопасным способом (флешка, зашифрованный архив, менеджер паролей). Положить в корень проекта.

Локальный `.env` — с локальным паролем базы; боевой живёт только на сервере и отличается. Их не путать.

### 2.2. Ключ доступа к серверу (если хотите деплоить с ноутбука)

Файлы `~/.ssh/ttc_vps` и `~/.ssh/ttc_vps.pub`. Без них не выйдет обновлять бота на VPS. Копировать так же аккуратно, как `.env`.

Проверка, что доехало:

```bash
ssh -i ~/.ssh/ttc_vps root@45.91.238.177 "docker compose -f /opt/ttc/docker-compose.yml ps"
```

Если Windows ругается на права ключа — можно не копировать ключ, а сгенерировать на ноутбуке новый и добавить его на сервер:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/ttc_vps -N '' -C 'ttc-laptop'
# затем добавить содержимое ~/.ssh/ttc_vps.pub в панели Timeweb или в /root/.ssh/authorized_keys на сервере
```

### 2.3. Настройки Claude Code

Скопировать с компьютера на ноутбук (пути одинаковые, только имя пользователя своё):

| Что | Путь | Зачем |
|---|---|---|
| Общие правила | `~/.claude/CLAUDE.md` | Общение по-русски, обязанность вести PROJECT.md, поправка на голосовой ввод |
| Скиллы | `~/.claude/skills/project-state/` и `~/.claude/skills/project-load/` | Те самые `/project-load` и ведение PROJECT.md |
| Память | `~/.claude/projects/<папка проекта>/memory/` | Накопленные заметки о ваших предпочтениях |

**Про `<папка проекта>`.** Claude Code делает имя папки из пути к проекту (`c:\Users\Черешня\Python\TTC` превращается в `c--Users---------Python-TTC` — все необычные символы становятся дефисами). На ноутбуке имя пользователя другое, значит и папка будет называться иначе. Поэтому проще так: запустите Claude в проекте один раз, потом посмотрите, какая папка появилась в `~/.claude/projects/`, и скопируйте `memory/` уже туда.

**Не копируйте `~/.claude/.credentials.json`** — это ваш вход в аккаунт. На ноутбуке просто войдите заново при первом запуске.

## 3. Как начинать работу на любом из компьютеров

```bash
git pull          # ОБЯЗАТЕЛЬНО первым делом
claude            # запустить Claude Code в папке проекта
/project-load     # Claude прочитает PROJECT.md и восстановит понимание проекта
```

И в конце работы:

```bash
git push          # чтобы второй компьютер увидел изменения
```

Это и есть весь ритуал. PROJECT.md обновляется после каждого блока работы, поэтому на другом компьютере вы продолжаете ровно с того места, где закончили — включая «что осталось сделать» и «что заблокировано».

## 4. Чего делать не надо

- **Не запускайте бота локально, пока работает боевой на сервере.** Telegram отдаёт сообщения только одному экземпляру; два начнут отнимать их друг у друга, и оба будут сбоить. Локально можно поднимать только базу: `docker compose up -d postgres redis`.
- **Не работайте на двух компьютерах одновременно без `git pull`.** Иначе получите конфликт в PROJECT.md — файл большой и правится почти каждую сессию. Правило простое: закончил — `push`, начал — `pull`.
- **Не копируйте `.env` через мессенджеры и почту.** Там боевой токен бота: кто его получил, тот управляет ботом.

## 5. Можно ли перенести саму переписку с Claude

Технически да: история сессии — это файл `.jsonl` в `~/.claude/projects/<папка проекта>/`. Скопируете его в такую же папку на ноутбуке — сессия появится в списке `claude --resume`.

Но на практике это того не стоит: файл текущей сессии весит около 17 МБ и растёт, а переносить его придётся каждый раз при пересадке за другой компьютер. PROJECT.md решает ту же задачу лучше — он маленький, читается за секунды, лежит в git и обновляется сам.

## 6. Ещё вариант: работать вообще без переноса

У Claude Code есть веб-версия на [claude.ai/code](https://claude.ai/code): она подключается прямо к репозиторию на GitHub, работает в облаке и не зависит от того, за каким компьютером вы сидите. Для правки кода и работы с документацией подходит; для запуска бота локально и деплоя по SSH — нет, там нужен ваш компьютер с ключом.
